# Архитектура проекта: RSS/Atom Reader

## 1. Слои приложения
Приложение строго разделено на три слоя (зависимости направлены сверху вниз):
- **Представление (TUI):** отвечает только за отрисовку интерфейса (на базе FTXUI/ncurses) и обработку нажатий клавиш пользователя. Не содержит бизнес-логики.
- **Слой приложения:** управляет сценариями работы, очередью фоновой загрузки по сети и состоянием сеанса.
- **Ядро (core):** содержит чистую модель предметной области (`Feed`, `Article`), парсеры XML/HTML и логику кэширования. Не знает ничего о терминале.

## 2. Точки расширения (Open/Closed Principle)
В архитектуру заложены следующие точки расширения, позволяющие добавлять функционал без правки существующего кода:
1. **Новый формат ленты:** добавление новых парсеров (например, JSON Feed или RSS 1.0) через общий интерфейс парсера.
2. **Новый элемент HTML:** добавление новых тегов и способов их отрисовки в текст терминала через полиморфные обработчики узлов дерева.
3. **Новый источник лент:** расширение способов получения данных (например, локальный файл вместо HTTP).
4. **Новый способ хранения состояния:** абстракция над хранилищем прочитанных статей и подписок.

## 3. Паттерны проектирования (GoF)
В проекте планируется использовать следующие паттерны:
- **Порождающий:** *Фабричный метод (Factory Method)* — для выбора нужного парсера в зависимости от формата входящего документа (RSS 2.0 или Atom 1.0).
- **Структурный:** *Компоновщик (Composite)* — для обхода дерева элементов HTML при конвертации в текст терминала.
- **Поведенческий:** *Наблюдатель (Observer)* — для уведомления интерфейса о завершении фоновой сетевой загрузки ленты.
- **Поведенческий** *Стратегия (Strategy)* - для сменяемых алгоритмов сортировки фильтрации списка статей.
